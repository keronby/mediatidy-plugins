# 剧集查重 · 流程说明（给 AI 读）

本文件描述 mt-console「影视查重」模块在**剧集（TV）场景**下的完整工作流程。
读者按此文档即可复现、修改或重写这套逻辑，不需要先读源码。

---

## 0. 一句话

> 扫描 `strm` 剧集库 → 按 `{tmdb-<id>}` 归组 → 强制刷新 MT 的 TMDB 缓存拿到官方最新标题/年份 → 逐目录比对片名与年份 → 标出「需要重整」的目录 → 按 strm 链接属性分流（本地整理 / 云盘整理）→ 提交 MT 整理任务。

---

## 1. 术语与数据前提

| 术语 | 含义 |
|---|---|
| 作品目录 | 形如 `101次抢婚 (2023) {tmdb-222531}` 的目录名，内含 `Season N/` 子目录、`poster.jpg`、`backdrop.jpg`、`logo.png` |
| strm 文件 | 播放指针。剧集为 `作品.年份.S01E01.2160p.SDR.10-bit.60fps.25.2Mbps.H265.AAC.strm`，同集还带 `.nfo` 与 `-mediainfo.json` |
| `link_type` | strm 首行的形态：`http(s)://...` → `http`（分享链）；包含 `/cloudnas` 或 `/vol1` → `cloudnas`（本地/CD2 挂载）；其它 → `other` |
| `tmdb_id` | 从目录名中的 `{tmdb-123}`、`[tmdbid=123]`、`[tmdb-123]`、`[tmdb_id=123]`、`（tmdbid=123）` 提取 |
| MT | MediaTidy，负责真正的识别与整理。本模块只负责**判定**并把任务交给 MT |
| Profile | MT 的整理方案。本地整理默认 `1359`（strm整理），云盘整理默认 `854`（手动识别-媒体库） |

**真实剧集库规模（2026-10 实测）**：`/vol1/1000/strm/云盘影视/电视剧` 下 11835 个作品目录，顶层分类为 `国产剧 / 日韩剧 / 欧美剧 / 港台剧 / 特摄剧 / 综艺 / 纪录片`。

## 2. 全流程七步

### 第 1 步 · 扫描目录树

入口：`scan_duplicates(root_path)`

1. `root_path` 缺省时取 `media_dedup_config.json` 的 `root_path`，再缺省为 `/vol1/1000/strm/云盘影视`。
2. 路径映射 `resolve_local_path()`：同时兼容宿主机路径 `/vol1/1000/strm/...` 与 MT 容器内路径 `/strm/...`，哪边存在用哪边。
3. 顶层分类识别用 `kind_map`：`电影/movie/movies` → `movie`；`电视剧/剧集/tv/shows/anime/动漫` → `tv`。
4. 向下递归最多三层寻找带 tmdb 标签的目录，**扁平单层结构**（`电视剧/国产剧/<作品>`）与**根目录直挂作品**都支持。
5. 每个作品目录产出一条 item：

```python
{
  "category": "国产剧",              # 分类名（用于判断分类冲突）
  "dir_name": "101次抢婚 (2023) {tmdb-222531}",
  "dir_path": "/vol1/1000/strm/云盘影视/电视剧/国产剧/101次抢婚 (2023) {tmdb-222531}",
  "mt_path": "/strm/云盘影视/电视剧/国产剧/101次抢婚 (2023) {tmdb-222531}",
  "local_title": "101次抢婚",
  "year": "2023",
  "tmdb_id": 222531,
  "media_type": "tv"
}
```

目录名解析（`parse_media_dir`）：tmdb 标签剥离后，年份优先取括号 `(2023)`、`（2023）`、`[2023]`；再取点分末段 `...2023`；最后取前缀里最后一个四位年份。

### 第 2 步 · 归组（⚠ 关键限制）

```python
if len(dirs) > 1:      # 同一 tmdb_id 下出现 ≥2 个目录才算“重复组”
    dups_by_kind[media_type][tid] = dirs
```

**只有同一个 `tmdb_id` 对应多个目录时才进入后续全部检查。**
单一目录的作品**不会**被比对标题/年份。

实测（`/vol1/1000/strm/云盘影视/电视剧`）：
- 11835 个作品目录，11816 个不同 tmdb_id
- **多目录（≥2）：19 个 tmdb_id / 38 个目录**
- **单一目录：11797 个 tmdb_id** ← 这 99.8% 目前完全不参与比对

> 若目标是「检查全库所有剧集目录是否与 TMDB 不一致」，必须改动此处（见第 7 节）。

### 第 3 步 · 读 strm 判链接属性

`analyze_strm_files(dir_path, dir_name)` 逐个读 `.strm` 首行：

| 首行特征 | `link_type` | 说明 |
|---|---|---|
| `http://` 或 `https://` | `http` | 分享链。sha1、fileName 直接写在 URL 参数里 |
| 含 `/cloudnas` 或 `/vol1` | `cloudnas` | CD2 本地挂载路径，同时提取 `cloudnas_dir` 真实云盘路径 |
| 其它 | `other` | 视为本地 |

组级聚合 `group_link_type`：
- 组内全部 `http` → `all_http`
- 组内全部 `cloudnas` → `all_cloudnas`
- 混合 → `mixed`（**禁止自动处理**）

### 第 4 步 · 从 MT 取官方最新标题/年份

两条路径，缺一不可：

**4a. 读 MT 数据库缓存**（`query_mt_tmdb_caches`）
直连 `file:/vol1/1000/docker/mediatidy/data/mediatidy.db?mode=ro`，查 `tmdb_cache` 表的
`tmdb_id, media_type, id, title, original_title, year, poster_path, updated_at`，按 500 条一批。

**4b. 强制刷新**（`refresh_tmdb_for_duplicates` / `refresh_single_tmdb`）
1. 用 `tmdb_id` 在 `/api/tmdb-cache?search=<id>` 找到 `cache_id`（`id` 字段）；
2. `POST /api/tmdb-cache/<cache_id>/refresh`；
3. 取返回的 `data` 里最新 `title / originalTitle / year / posterPath`；为空则 `sleep(1.0)` 后重查一次；
4. 5 线程并发（`ThreadPoolExecutor(max_workers=5)`），支持中途停止。

> 提交整理前，`submit_organize_tasks` 默认 `force_refresh_tmdb=True`，会**先刷新一遍再比对再提交**。这是硬要求：不刷新会拿到过期标题，导致误判或漏判（历史上 MT 因此报过 `TMDB 目前只有 -1 季`）。

### 第 5 步 · 比对判定（`evaluate_dir_match`）

```
片名：clean_title_invisible_chars(local_title) == clean_title_invisible_chars(latest_title)
      严格全等。不是「包含」、不是「相似」。
      对比前先清洗零宽字符：\u200b ~ \u200f 与 \ufeff
      （TMDB 官方数据确实带过 \u200b，会造出两个肉眼完全相同的目录）

年份：latest_year 有值时
      本地 year 缺失        → 不一致，reason = "年份缺失 (TMDB应为 2026)"
      本地 year != 官方     → 不一致，reason = "年份不符 (当前为 1975，TMDB应为 1974)"
      本地 year == 官方     → 一致

结果：(is_matched, need_organize, diff_reason)
任一项不一致 → need_organize = True
```

**分类冲突**（`reevaluate_group_dirs`，仅对进入扫描的多目录组生效）：

```
distinct_cats = sorted(set(目录的 category))
if len(distinct_cats) > 1:            # 例如 国产剧 vs 综艺、国产剧 vs 港台剧
    组内每个目录都 need_organize = True
    diff_reason += " · 分类不同 (本目录: 国产剧 ➜ 组内存在其他分类: 综艺)"
```

**混合链接拦截**：`link_type == "mixed"` 或组级 `mixed` → `disabled = True`，
`disabled_reason = "含混合链接(暂不支持自动处理)"`，不计入待整理数，**永不提交**。

### 第 6 步 · 按链接属性分流提交

`submit_organize_tasks(...)`：

| `link_type` | 传给 MT 的路径 | 方案 | 目标目录 |
|---|---|---|---|
| `http`（分享链） | 剥离 `/vol1/1000` 前缀，得到 `/strm/云盘影视/...` | `1359` strm整理（本地整理） | `/strm/云盘影视` |
| `cloudnas`（本地链） | 优先用 strm 内容里提取的真实云盘路径；否则 `/strm/...` → `/115open/...` | `854` 手动识别-媒体库（云盘整理） | `/小小玻珠/云盘影视` |

提交请求：

```json
POST /api/organize/manual
{
  "profileId": 1359,
  "tmdbId": 222531,
  "mediaType": "tv",
  "sourceDir": "/strm/云盘影视/电视剧/国产剧/101次抢婚 (2023) {tmdb-222531}",
  "destDir": "/strm/云盘影视"
}
```

跳过规则（按先后）：
1. `disabled` 或 `link_type == "mixed"` → 跳过，记「该目录含混合链接，暂不支持自动整理」
2. `only_difference=True` 且 `need_organize == False` → 跳过
   - **例外**：`force_manual=True` 或该项 `manual=True`（用户手动点单条）时放行，日志打 `[提交整理][手动放行]`
3. 用户点「停止」→ 打 `[提交整理][中止]` 并 `break`

### 第 7 步 · 结果回读与验证

- 扫描结果持久化到 `media_dedup_scan.json`，重启不丢。
- `POST /api/duplicate/verify` 用 `MTClient.task_outcome(task_id, tmdb_id)` 轮询 MT 最近 60 条任务（最多 25 秒），返回：
  - `done`：`完成：N/N 个文件已整理入库`
  - `noop`：`完成：N 个文件已在库中、无需重复整理，多余目录已清理`（**这是正常结果，不是失败**）
  - `running` / `queued` / `failed` / `unknown`
- `POST /api/duplicate/history/clear` 删历史记录文件（不动任何媒体文件）。

## 5. 实现要点 · 别踩的坑

1. **规则/缓存的读法**：`tmdb_cache` 里 `sections.seasons[].episodes` 是空数组，MT 缓存**不存分集列表**。要分集信息必须直接查 TMDB API。
2. **`created_at` 是空格分隔**（`2026-10-20 13:36:08`），用 ISO 的 `T` 查会得 0 条。
3. **`organize_records` 没有 `error` 列**，错误在 `status_reason_code` / `last_operation_errors`。
4. **`/api/organize/manual` 返回的 `data.id` 不是 MT task id**，只是受理标识。真实 task id 要另查 `/api/organize/tasks`。
5. **`/api/organize/tasks` 返回的 `data` 是 list 不是 dict**。
6. **`deleted` / `superseded` 是正常终态**（洗版拒绝、下游 profile 接管），不是失败。
7. **提交成功 ≠ 入库**：MT 受理后下游 profile 会用新文件名再识别一次，剥标题比我们激进。若剥剩的是 TMDB 标题的短前缀（如 `Do Us Part` → `Do Us`），会被退回未识别，且**重提多少次都不会成功**。这类目录应在提交前拦住。
8. **零宽字符**：TMDB 官方数据出现过 `\u200b`，会造出两个肉眼相同的目录（如 `借颜 (2026)` 与 `借颜 (2026)`）。比对前必须清洗。
9. **单例目录不参与比对**：见第 2 步限制。
10. **不要在容器内跑长任务**：容器重启会让进程卡 D 状态，`kill -9` 无效，只能重启容器。长扫描放宿主机。

## 6. 已知边界（当前不处理）

| 情况 | 现状 |
|---|---|
| 单一目录作品的标题/年份不一致 | **不检查**（只查多目录组） |
| 跨目录同 tmdb（如 `乘风` vs `乘风破浪的姐姐`） | 会因多目录而检出，但若分类相同且片名年份都对得上则不报 |
| 连集包 `S01E01-E02` 与单集 `S01E01` 并存 | 视为不同集号，**不互相比、不报重复** |
| 混合链接组 | 明确禁用，不提交 |
| 真正的“同集多版本”查重 | 本模块不做（那是 `strm查重` 的职责） |

## 7. 若要扩展到全库检查（改造清单）

当前实现只覆盖 19/11816 个剧集 tmdb_id。要变成「检查全库每个目录」：

1. **改归组条件**：把 `if len(dirs) > 1` 改为对 `raw_groups` 里**所有** item 都生成组（单目录组 `dirs` 长度为 1）。
2. **改统计口径**：`*_duplicate_groups` 字段名不再准确，需新增 `single_dir_groups` / `all_groups`。
3. **改前端**：`MediaDedup.vue` 的「重复组」标签与过滤器需重构，区分「多目录组」与「单目录不一致」。
4. **控制规模**：全库 11835 个目录，若逐个 `refresh` 会大量打 MT 接口。建议：
   - 先用 `query_mt_tmdb_caches` 批量读缓存做**首轮粗筛**（零网络）；
   - 只对「疑似不一致」的条目再 `refresh` 复核。
5. **确认分集数**：若要同时查「季集数不符」，需查 TMDB `/tv/<id>/season/<n>` 对比本地 strm 的集号集合——目前完全没有这一步。

## 8. 最小复现脚本（宿主机，只读）

```python
import os, re
from collections import defaultdict

ROOT = "/vol1/1000/strm/云盘影视/电视剧"
TAG = re.compile(r'[\[\{（(]\s*tmdb(?:id|\s*_?id)?\s*[=:\-]\s*(\d+)\s*[\]\}）)]', re.I)

by_tid = defaultdict(list)
for cat in sorted(os.listdir(ROOT)):
    cp = os.path.join(ROOT, cat)
    if not os.path.isdir(cp):
        continue
    for sub in sorted(os.listdir(cp)):
        sp = os.path.join(cp, sub)
        if not os.path.isdir(sp):
            continue
        m = TAG.search(sub)
        if m:
            by_tid[m.group(1)].append((cat, sub))
        else:
            for d in sorted(os.listdir(sp)):
                if TAG.search(d):
                    by_tid[TAG.search(d).group(1)].append((cat + "/" + sub, d))

dups = {k: v for k, v in by_tid.items() if len(v) > 1}
print("作品目录:", sum(len(v) for v in by_tid.values()))
print("多目录组:", len(dups), "单一目录:", len(by_tid) - len(dups))
```

预期输出（2026-10 实测）：

```
作品目录: 11835
多目录组: 19 单一目录: 11797
```
